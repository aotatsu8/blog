「いつかゲームを作ってみたい」——そう思ったまま、何年も放置していました。

理由ははっきりしています。**何から手をつければいいか、まったく分からなかったから**です。普段はWebのフロントエンドを書いていますが、ゲームは完全に別世界。当たり判定も、ゲームループも、敵の湧かせ方も、知識はゼロでした。

その状態から、AIに手伝ってもらって2週間。ブラウザゲームを1本作り、世界に公開して、<strong>実際に収益が発生しました。</strong>金額は本当に小銭です。それでも、この記事で伝えたいことは全部そこに詰まっています。

作ったのは **Prism Survivor** というネオン風のサバイバルシューティングです。まずは3分だけ触ってもらえると、この先の話が入ってきやすいと思います。

- ▶ [Y8 で遊ぶ](https://ja.y8.com/games/prism_survivor)
- ▶ [GamePix で遊ぶ](https://www.gamepix.com/play/prism-survivor)

## 結論：未経験でも「公開まで」は2週間で届く

先に結論を書きます。**ゲーム開発の知識がなくても、AIと組めば「動いて、公開できて、人に遊ばれる」ところまでは2週間で行けます。**

そう言い切れる理由は、個人開発の失敗のほとんどが「実力不足」ではなく<strong>「途中で止まること」</strong>だからです。分からない用語を調べ、記事を漁り、うまく動かず、翌日には熱が冷めている。作りきれない原因は、だいたいこの停滞にあります。

AIはここを潰してくれます。分からない場面で手を止めず、**その場で動くコードを見ながら判断できる**。作業が「調べる」から「確かめて直す」に変わるので、勢いが死なない。今回2週間で形になったのは、才能でも根性でもなく、単純に**止まっている時間がほぼゼロだった**からです。

## どんなゲームを作ったのか

Prism Survivor は、いわゆる<strong>「サバイバー系」</strong>と呼ばれるジャンルのブラウザゲームです。敵の群れをさばきながら生き延び、レベルアップのたびに自分の武器構成を育てていく——あの手触りを、1プレイ数分に圧縮しました。

ルールはシンプルです。

- 画面が常に下へ引きずられ、下部の**バーンゾーン**に落ちたら終わり
- 武器は**自動で発射**される。プレイヤーは「どこに立つか」だけに集中する
- レベルアップで**カードを選んでビルドを強化**（武器は最大4つ＋パッシブ）
- **30秒×8ウェーブ**を耐え抜けばクリア

技術的には **Phaser（HTML5のゲームフレームワーク）** を使いました。理由は明確で、**ブラウザだけで完結するから**です。インストールもストア審査も不要、URLを開けばPCでもスマホでも即プレイ。個人開発において<strong>「遊んでもらうまでの手間の少なさ」</strong>は、そのまま遊ばれる回数に直結します。

操作もそこに合わせました。PCは矢印キー／WASD／マウスドラッグ、スマホは画面をドラッグするだけ。**チュートリアルを読まなくても動かせる**ことを最優先にしています。

## AIの何が凄かったのか、具体的に書く

「AIすごい」で終わらせると何も伝わらないので、実際に効いた場面を3つに絞ります。

### 1. 最初の壁は、コードより「何を作るか」だった

意外だったのは、AIがいちばん効いたのが実装前だったことです。

ゲームを作ろうとして最初に固まるのは、**面白さの設計**でした。難易度をどう上げるか、1プレイを何分にするか、レベルアップは何秒おきが気持ちいいのか。答えを持っていないので、そもそも手が動かない。

そこで相談相手としてAIを使いました。「ブラウザで数分で終わるサバイバー系にしたい」と投げれば、ウェーブの区切り方や敵の増やし方の案が返ってきます。**叩き台が目の前にあるだけで、判断は一気にラクになる**。今の「30秒×8ウェーブ」も、この壁打ちから生まれた形です。

### 2. Claude Code のおかげで、詰まる時間が消えた

実装は Claude Code に任せる場面が多かったです。ターミナルからそのままファイルを読んで直してくれるので、**エラーをコピペして貼り直す往復すら発生しません。**

当たり判定が抜ける、倒し損ねた敵が画面外に溜まる、レベルアップ画面でゲームが止まらない。初心者が必ず踏む地雷を、状況を説明するだけで踏み抜けていける感覚でした。

ただし、ここには前提があります。**出てきたコードをそのまま信じないこと。**必ず自分で遊んで挙動を確かめ、おかしければ差し戻す。作る人から**レビューする人**に役割が変わる、というのが今回いちばん大きな実感でした。

### 3. 絵と音の壁が消えたのが決定的だった

個人開発が本当に詰むのは、コードではなく**アセット**です。絵が描けない、音が作れない。ここで大半の企画が止まります。僕もそうでした。

今回は画像・音まわりも生成AIに頼りました。**ネオン調**という方向性を先に決めて、それに合う素材を揃えていく。結果として、見た目のトーンが揃ったゲームを一人で用意できました。

<strong>「絵が描けないから作れない」</strong>という言い訳が、もう成立しない。技術的な進歩以上に、この事実のほうが個人開発者にとっては大きい変化だと思います。

## 収益化：どこに置いて、いくらになったのか

そしてタイトルの「収益」の話です。

やったことは単純で、**完成したゲームをゲームポータルに公開し、広告収益をシェアしてもらう**形にしました。使ったのは次の2つです。

- **[GamePix](https://www.gamepix.com/play/prism-survivor)**: HTML5ゲームの配信プラットフォーム。プレイ数に応じて広告収益が分配される
- **[Y8](https://ja.y8.com/games/prism_survivor)**: 世界中で遊ばれている老舗のブラウザゲームポータル

ここが個人開発と相性抜群でした。**自分でサーバーを用意する必要も、集客を頑張る必要もない。**「人がすでに集まっている場所」に置かせてもらうだけで、公開直後から知らない国の誰かが遊んでくれます。

肝心の金額は、正直に書くと**ジュースが何本か買える程度**。生活は1ミリも変わりません。

それでも、<strong>「自分が作ったものが、自分の見ていないところで遊ばれ、1円でもお金になった」</strong>という事実の重さは想像以上でした。0円と1円の間には、1円と1万円よりも大きな壁がある。その壁を一度越えられたことが、今回いちばんの収穫です。

## うまくいかなかったところ

良い話だけだと嘘くさいので、つまずいた点も残しておきます。

- **バランス調整だけはAIに丸投げできない**: 「難しすぎる／簡単すぎる」は自分で何十回も遊んで詰めるしかありませんでした。結局ここが最長工程です。
- **スマホの操作感は実機でしか分からない**: PCで気持ちよくても、スマホでは自分の指で敵が隠れる。触るまで気づけませんでした。
- **完成＝公開ではない**: プラットフォームごとに画面サイズ・サムネイル・説明文などの要件があり、その対応が地味に効いてきます。
- **作り込みすぎた**: 誰も気づかない部分に時間を使いました。**小さく出して、反応を見てから足す**ほうが確実に速いです。

## まとめ：完璧を目指すより、公開まで持っていく

今回の学びを整理します。

- **ゲーム開発未経験でも、AIと組めば2週間で公開まで届く**
- AIの真価はコード生成そのものより、**手を止めさせないこと**にある
- 生成AIで絵と音も用意できるので、**アセットの壁はもう言い訳にならない**
- 公開はゲームポータル（GamePix / Y8 など）に任せると、集客と収益化までまとめて乗せられる
- 収益は小銭。それでも**0→1を越えた経験の価値は、金額とは別の場所にある**

もし「作ってみたいけど自分には無理」と思っているなら、いま試す価値はかなり高いと思います。<strong>未完成でもいいので、とにかく公開まで一度やり切る。</strong>そこまで行くと、次に何を作るべきかが自然と見えてきます。
